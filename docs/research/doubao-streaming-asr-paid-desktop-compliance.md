# 豆包流式语音识别用于 Saymore 付费版的合规与并发调研

调研日期：2026-07-24

范围：Saymore
作为付费桌面软件，由开发者统一充值火山引擎豆包流式语音识别额度，终端用户使用云端
ASR；不自建传统常驻服务器。本文只引用火山引擎/字节跳动第一方资料和中国政府官方法规。

> 本文是产品与工程侧合规核查，不是法律意见。正式商业发布前，应让实际签约主体的律师复核隐私政策、用户协议和数据处理流程，并就“付费桌面软件向终端用户提供开发者统一采购的
> ASR 能力”取得火山引擎书面确认。

## 结论摘要

1. **把火山引擎 ASR
   集成进商业软件，原则上属于官方协议预期的客户产品场景。**《产品和服务协议》明确提到客户的网站、客户端、应用、小程序和智能终端应用，并由客户自行运营、承担责任；官方还提供直接在
   Android/iOS 客户端配置 AppID 和 Access Token 的流式识别 SDK
   文档。因此“客户端调用”本身不是禁止形态。[产品和服务协议](https://www.volcengine.com/docs/6256/68938?lang=zh)
   [大模型流式识别 SDK](https://www.volcengine.com/docs/6561/1395846?lang=zh)
2. **公开条款没有明确授权把云服务本身、统一账号或凭证转售给不特定终端用户。**《产品和服务协议》第
   5.5 条还限制未经明示许可转许可、发布或转让产品和服务及权限密钥。卖的是带 ASR
   功能的 Saymore 软件，和转售火山引擎账号/API
   额度不是同一件事；但把统一长期凭证随客户端分发会直接触及这条边界。发布前应向火山引擎提交完整业务说明，书面确认商业模式、凭证下发方式、终端用户范围和并发购买方式。[产品和服务协议](https://www.volcengine.com/docs/6256/68938?lang=zh)
3. **“开发者统一充值 + 完全无可信后端 +
   公开发行客户端”在安全上不可成立。**安装包内的统一 API Key 或 Access Token
   可被提取并脱离 Saymore
   盗刷；代码混淆和系统钥匙串只能提高提取成本，不能保住随软件分发且调用时必须使用的共享秘密。官方通用凭证安全说明也明确不建议客户端保存长期
   AK/SK，推荐服务端换取临时凭证。[火山引擎 STS 凭证安全说明](https://www.volcengine.com/docs/86081/1660350)
4. **提高并发配额可以解决供应商容量，但不能解决密钥、授权、风控和成本归属。**豆包大模型双向流式识别正式版默认
   `10`
   路并发，以控制台为准；小时版不够用时需由控制台/商务确认能否调额，或改购并发计费版。“流式输入”模式则默认最高
   `20 QPS`，并有半小时提交音频总时长不超过 500
   小时的限制。[语音识别大模型说明](https://www.volcengine.com/docs/6561/1354871?lang=zh)
5. **小时版和并发版是两种替代计费 SKU，不应理解成“小时包 +
   普通并发扩容包”。**小时版也有并发上限：双向流式正式版默认 `10`
   路，以控制台为准；仅购买更多时长不会自动提升该上限。官方资料能确认 1.0 小时版
   `volc.bigasr.sauc.duration` 和 1.0 并发版 `volc.bigasr.sauc.concurrent`
   同时存在，但公开资料不足以证明 ASR
   并发版一定免时长费，也未公开统一的月费/年费。因此必须以控制台订单或商务书面报价确认二者是否互斥、并发版计费周期及是否另收时长费。[QPS/并发查询接口](https://www.volcengine.com/docs/6561/1476626?lang=zh)
   [服务用量与额度预警](https://www.volcengine.com/docs/6561/1359373?lang=zh)
6. **无自有后端时，唯一相对稳妥的直接连接模式是
   BYOK。**即每位用户使用自己的火山引擎账号、AppID 和 Access Token，Saymore
   只收软件许可费；这与“开发者统一充值”目标冲突，但避免共享凭证和统一账单被盗刷。如果必须由开发者付
   ASR
   费用，应接受一个最小可信后端或由火山引擎书面提供等价的短期、可撤销、按终端用户限权凭证方案。
7. **分销身份不等于统一密钥公发权。**官方分销协议中的最终客户是公司、企业或组织，并通过自己的关联火山引擎账号下单和消费；其内部实际使用者才是“用户”。公开
   ASR 文档只列控制台生成的 `X-Api-Key`，或旧版 AppID + Access
   Token，没有找到可绑定终端用户、短期有效、可撤销和限额的 `openspeech`
   WebSocket 令牌。企业客户分销可让客户使用自己的账号凭证直连；Saymore
   面向个人统一付费时应经最小代理，除非火山引擎另行书面提供专用终端令牌方案。

## 一、商业使用与账号要求

### 1. 商业集成有依据，但“转售”边界需书面确认

火山引擎《产品和服务协议》把“客户产品”定义为客户运营的网站、客户端、应用、小程序及其他智能终端程序，客户对其中的产品、服务和内容自行负责；协议也要求双方持续具备经营活动所需的合法资质。该文本足以支持“客户采购技术服务并将能力集成到自己的商业产品”这一通常形态，但没有找到允许客户把火山引擎账号、Access
Token 或裸 API
配额再次出售给第三方的公开条款。[产品和服务协议](https://www.volcengine.com/docs/6256/68938?lang=zh)

建议向火山引擎售前/工单提交以下书面描述，而不是只问“能不能商用”：

- Saymore 是付费桌面语音输入软件，不向用户展示或出售火山引擎账号/API 凭证；
- 开发者作为火山引擎合同客户统一承担调用费用，终端用户通过 Saymore 使用 ASR；
- 音频由终端设备直达火山引擎或经最小代理转发，不用于训练、广告或用户画像；
- 预计用户数、峰值同时识别会话数、单用户时长上限、地区和未成年人策略；
- 请求确认该模式属于“客户产品集成”而非未经许可的转售，并确认允许的终端鉴权方案。

官方条款还禁止未经书面同意公开宣称火山引擎是合作方或使用其商标。因此产品页面可客观披露“云端语音由北京火山引擎科技有限公司受托处理”，但不应擅自使用“官方合作”“联合出品”等营销表述或品牌标识。[产品和服务协议第 6.4 条](https://www.volcengine.com/docs/6256/68938?lang=zh)

### 2. 必须实名认证；商业主体建议企业认证

豆包语音快速入门要求登录并完成实名认证后开通服务；火山引擎账号说明也写明，进一步体验或购买产品需要实名认证。[豆包语音快速入门](https://www.volcengine.com/docs/6561/163043?lang=zh)
[账号注册流程](https://www.volcengine.com/docs/6261/64925?lang=zh)

公开资料没有证明大模型流式 ASR 一律只允许企业认证，但 Saymore
若由公司/个体经营主体收费，合同客户、软件运营者、收款开票主体和隐私政策中的个人信息处理者应尽量保持一致。企业认证可使用法人扫脸、对公账户或企业证件等方式；具体材料以认证页面为准。[企业实名认证方式](https://www.volcengine.com/docs/6261/940503?lang=zh)

此外，付费软件本身涉及经营、税务、消费者权益、应用商店及可能的软件备案要求，这些不因没有自建服务器而消失，也不属于豆包
API 条款能单独解决的范围。

## 二、隐私与数据处理义务

### 1. 无自建服务器不等于不处理个人信息

语音、转写文本和设备标识只要与已识别或可识别自然人有关，就可能属于个人信息。语音中还可能包含医疗健康、金融账户、行踪、未成年人信息，或在用于身份识别时构成生物识别信息，从而触发敏感个人信息规则。《个人信息保护法》要求处理活动具有合法基础、遵循最小必要、事前告知；处理敏感个人信息还要求特定目的、充分必要、严格保护，并通常取得单独同意。[个人信息保护法第 5、6、13、17、28 至 30 条](https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)

火山引擎的流式语音识别 SDK
隐私政策也明确：开发者是个人信息处理者，火山引擎按开发者委托和指示处理；开发者应向终端用户披露
SDK 名称、提供者、处理信息种类及目的、隐私政策并取得同意。该政策还列出 SDK
可能采集的设备信息和标识，因此若 Saymore 实际集成
SDK，必须逐项核对版本和实际采集行为；若只使用自研 WebSocket
客户端，则应按真实网络请求披露，不能照抄移动 SDK
清单。[流式语音识别 SDK 隐私政策](https://www.volcengine.com/docs/6561/108794?lang=zh)

### 2. Saymore 上线前至少要完成的隐私动作

- 首次启用云端识别前单独说明：音频和识别所需上下文将发送给北京火山引擎科技有限公司，目的为实时转写，说明数据类型、处理方式、保存期限或确定方法、退出方式和隐私政策链接；用户主动选择云端模式后再申请麦克风权限。
- 本地识别继续作为不上传音频的可选路径；拒绝云端处理不应影响与云端无关的本地功能。
- 对可能包含敏感个人信息的自由听写场景采用单独同意，并提示用户不要录入无权提供的第三方敏感信息、国家秘密或工作秘密。
- 提供撤回同意、停止云端识别、删除本地历史、投诉和个人信息请求渠道；发生处理目的、种类、方式或保存期限变化时重新告知并依法重新取得同意。
- 对未满 14 周岁用户建立监护人同意和专门规则，或者在首发阶段明确不面向未满 14
  周岁用户。
- 不把音频、转写或热词用于训练、广告、画像、遥测或产品改进，除非另行证明必要性并取得适用授权。

监管部门的《App
违法违规收集使用个人信息行为认定方法》明确把“客户端未经同意直接向第三方提供个人信息”、未逐一披露第三方处理目的/方式/范围、同意前采集以及无撤回路径列为问题行为。[国家市场监督管理总局发布文本](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/rzjgs/art/2023/art_71e1f20c15e848428b218b88a4407ed4.html)

### 3. 与火山引擎的数据处理关系

火山引擎 DPA
把声音、文本等定义为客户数据，约定客户通常是个人信息处理者/委托方，火山引擎是受托方；火山引擎按客户指令处理，不用于用户商业画像、广告或市场调研，除非符合客户指令、服务要求或另获用户单独授权。DPA
还约定默认在中国大陆存储和处理、公共网络传输加密、采用最小权限，并在处理目的完成或停止服务后按约定和法律要求删除或匿名化。[火山引擎数据保护协议](https://www.volcengine.com/docs/undefined/67493?lang=zh)

《个人信息保护法》第 21 条和《网络数据安全管理条例》第 12
条要求委托处理时约定目的、期限、方式、种类、保护措施及双方权利义务，并监督受托方。签约/开通时应保存当时版本的主协议、DPA、产品专用条款和订单，形成供应商评估记录，而不只是放一个网页链接。[个人信息保护法](https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)
[网络数据安全管理条例](https://xzfg.moj.gov.cn/front/law/detail?LawID=1734)

仍需向火山引擎书面确认当前所购 ASR SKU
的具体日志字段、音频/转写缓存时长、故障排查访问机制、获准转委托方和删除响应流程。通用
DPA 给出了原则，但公开资料没有给出该实时 ASR SKU 的精确留存分钟数。

## 三、产品、计费与并发

### 1. 应购买的产品

Saymore
实时语音输入应使用豆包语音“语音识别大模型”下的**大模型流式语音识别**，而不是录音文件识别。官方提供双向流式模式（边说边返回）和流式输入模式（上传音频流后按句返回）；前者更符合桌面听写的低延迟要求。接口使用
WebSocket，主 API
文档及目录见官方资料。[产品能力与限制](https://www.volcengine.com/docs/6561/1354871?lang=zh)
[API 目录](https://www.volcengine.com/docs/6561/1354867?lang=zh)
[大模型流式 API](https://www.volcengine.com/docs/6561/1354869?lang=zh)

新购时必须在控制台确认模型/SKU 版本。官方 RTC 文档把 `volc.bigasr.sauc.duration`
标为 1.0 小时版，把 `volc.seedasr.sauc.duration` 标为 2.0
小时版；不要把两个版本的价格、资源 ID
和能力混用。[火山 ASR 资源 ID 对照](https://www.volcengine.com/docs/6348/1807452?lang=zh)

### 2. 计费口径

官方资料确认存在试用额度、预付费时长资源包、按调用时长后付费，以及**并发计费版**。这里的并发版是替代计费
SKU，不是小时版的普通扩容附件；小时版自身同样受并发上限约束。若小时版默认/当前并发不足，应先在控制台确认可否调整该
SKU
的上限，或由商务给出迁移到并发版的书面报价。[豆包语音快速入门](https://www.volcengine.com/docs/6561/163043?lang=zh)

截至调研日，公开页面价格口径不一致，不能直接拿一个数字做商业承诺：火山引擎首页对语音识别模型
2.0 展示流式识别 `1.0 元/小时`，豆包产品页仍展示 `4.5 元/小时`，ASR
产品页还有限时资源包价格。这些可能对应不同版本、渠道、刊例价和活动价。[火山引擎首页](https://www.volcengine.com/)
[豆包产品价格页](https://www.volcengine.com/product/doubao)
[ASR 产品页](https://www.volcengine.com/product/asr)

因此商业测算必须以实际登录账号中所选 SKU
的订单页为准，并保存报价/订单快照。公开第一方资料没有给出 ASR
并发版“每路每月/每年”的统一价格，也没有明确说明它是否完全替代时长费。官方其他语音产品中出现过“纯并发、不按字符计费”的表述，但那是语音合成/声音复刻，不得套用到
ASR。[产品动态](https://www.volcengine.com/docs/6561/162929?lang=zh)

下单前要求订单或商务邮件逐项写明：模型版本、资源
ID、计费单位、合同周期、并发版是否仍扣时长包或产生时长费、最低购买量、未使用容量是否过期、扩缩容/退款、突发超额、税费和发票。拿不到这些确认时，财务模型只能按“并发固定费和时长费都可能发生”的保守情形计算。

### 3. 并发与 QPS 不是一回事

| 模式     | 官方默认正式版限制                             | Saymore 应如何理解                                  |
| -------- | ---------------------------------------------- | --------------------------------------------------- |
| 双向流式 | 默认 10 并发，以控制台为准                     | 同时保持的活跃识别 WebSocket 会话容量，适合实时听写 |
| 流式输入 | 默认最高 20 QPS；半小时提交音频不超过 500 小时 | 请求提交速率与窗口总量，不应拿来替代实时长连接并发  |

来源：[语音识别大模型说明](https://www.volcengine.com/docs/6561/1354871?lang=zh)

官方配额查询接口的 `value` 表示实际 QPS/并发用量，`limit`
表示开通或购买后的上限；小时版和并发版有不同资源
ID，但查询到配额并不等于证明两种费用会同时收取。控制台还能查看每天/每小时峰值并设置额度预警。[QPS/并发查询接口](https://www.volcengine.com/docs/6561/1476626?lang=zh)
[服务用量](https://www.volcengine.com/docs/6561/1359373?lang=zh)

采购的实际步骤是：完成实名认证，在豆包语音控制台创建应用、开通正式服务；在服务包/使用详情或费用中心选择小时版或并发版，并核对该
SKU 的并发上限。控制台没有目标规格时走工单或商务评估，不应通过创建多个 AppID
绕过配额。[豆包语音快速入门](https://www.volcengine.com/docs/6561/163043?lang=zh)

### 4. 容量规划

实时听写中，一名正在讲话的用户通常至少占一个活跃会话。默认 10 并发意味着最多约
10 个用户同时识别，不是只能有 10
个付费用户。应按峰值同时使用率而非总用户数采购：

```text
目标并发 = 峰值同时听写用户 + 重连/会话重叠余量 + 运维测试余量
```

建议先用 10 路正式版做小规模灰度，记录每分钟活跃连接、会话时长、拒绝次数和
`value / limit`，再按观测峰值留出 20% 至 30%
余量规划。大流量上线前应提前书面告知火山引擎；其 SLA
明确把超配额、客户密钥泄露、未遵循使用建议和未提前告知的大规模突发流量排除在可用性赔偿之外。[智能语音服务等级协议](https://www.volcengine.com/docs/6561/107349?lang=zh)

## 四、无自建服务器的架构选择

### 方案 A：每位用户自带火山引擎凭证（BYOK）

```text
用户设备 -> 豆包 WebSocket API
          用户自己的 AppID / Access Token / 账单 / 配额
```

这是完全无开发者后端时风险最低的方案。凭证只代表该用户自己的云账号，Saymore
可把它保存在操作系统凭证库中，且不得进入日志、崩溃报告或遥测。开发者只销售
Saymore 软件许可，不统一承担 ASR 调用费用。

缺点是每个用户都要注册、实名认证、开通和充值，商业体验较差；每个用户分别受自己的并发配额约束，也无法提供“一口价含云识别时长”。

### 方案 B：安装包内置开发者统一 API Key/Access Token

```text
所有用户设备 -> 豆包 WebSocket API
               同一个开发者长期调用凭证
```

**不建议上线。**官方客户端 SDK
说明证明终端直连在技术上受支持，但不能证明把一个开发者统一付费凭证公发给所有购买者是安全或获准的。任何购买者或恶意软件都可从进程内存、网络调用参数或逆向后的程序中提取
Token，并在 Saymore
外持续调用。后果包括盗刷、并发耗尽、无法区分合法用户、无法执行套餐上限或封禁，以及密钥泄露责任落到开发者。

为每个安装包写入不同 Token
只能缩小泄露范围，仍不能把桌面客户端变成可信执行环境；离线许可证也不能阻止提取后绕开客户端调用。

### 方案 C：最小托管控制面/代理（推荐给开发者统一付费模式）

```text
Saymore -> 付费授权与限流服务 -> 豆包流式 ASR
          统一密钥仅在可信环境
```

这不需要运维传统服务器，可以使用按量计费的托管容器、边缘函数或支持长 WebSocket
的 serverless 平台，但它仍然是一个后端。至少应承担：

- 校验 Saymore 付费授权和设备/账户会话；
- 每用户分钟数、同时会话数、总账户并发和预算限流；
- 在达到供应商额度前排队或明确返回繁忙；
- 统一凭证保密、轮换、撤销和异常调用阻断；
- 记录不含音频/转写内容的计量与安全日志。

最安全的是代理整条
WebSocket，使火山凭证永不下发。若火山引擎能为语音产品提供短期、最小权限、绑定
App/设备/额度且可撤销的临时令牌，也可只做令牌签发控制面；但当前公开语音 API
文档使用 AppID + Access Token，没有找到适用于该 `openspeech` 流式接口的 STS
临时凭证说明，因此不能假定通用 STS
可直接替代。应让火山引擎书面给出支持方案后再采用。

## 五、推荐决策

如果“完全不部署任何后端”是不可变条件，选择
**BYOK**，并把付费版定义为软件功能收费而不是包含开发者购买的云端额度。

如果“用户购买后直接可用、云端费用由开发者承担”是核心商业体验，接受一个极小的托管后端，并在**小时版或并发版**中选择总成本更合适且并发上限足够的
SKU。小时版并发不够时需要火山引擎调整上限或迁移计费版；不要预设可以在小时版上简单叠加并发包。

正式上线前的放行条件：

1. 火山引擎书面确认该商业模式不属于未经许可的转售，并批准终端鉴权/代理方式；
2. 签约主体完成适当实名认证，保存主协议、DPA、产品条款、订单和并发报价；
3. 隐私政策、云端识别单独告知/同意、第三方处理清单、撤回和删除路径上线；
4. 明确 ASR SKU 版本、时长单价、并发单价、资源 ID、默认和采购后上限；
5. 完成密钥泄露、盗刷、并发耗尽、欠费、供应商故障和用户撤回同意的演练；
6. 用真实灰度数据验证峰值并发、单用户成本、套餐毛利和 20% 至 30% 容量余量。

## 六、按 1 元采购、2 元销售的商业模型

### 1. 卖 Saymore 服务，不要卖“豆包小时”

更稳妥的产品形态是：用户购买 Saymore 会员或云识别服务，识别能力只能在 Saymore
内使用；用户拿不到火山引擎账号、API
地址、密钥或可转移额度。月度赠送权益应称为“Saymore
云识别分钟数/额度”，并明确有效期、是否结转、最小计费单位、失败请求是否扣费以及退款规则。

下列做法会明显接近
API/额度转售：把商品命名为“豆包小时充值”；按供应商单位一比一销售；向用户交付凭证或
API；允许脱离 Saymore
调用、转赠或提现；暗示获得火山引擎官方经销身份。仅把名称换成“会员权益”不能改变交易实质。

火山引擎确有正式的合作伙伴代售模式：获授权伙伴以自己名义向最终客户销售火山引擎产品并承担交易争议，配额用于渠道结算。这反向说明，若业务实质是转售云服务，应走正式授权渠道，而不是依赖普通客户账号。[分销合作伙伴客户关联协议](https://www.volcengine.com/docs/6256/1281947?lang=zh)

火山引擎通用服务条款还规定，未经书面同意不得赠与、出借、出租、转让、售卖账号或许可他人使用。产品专用条款中也反复采用“仅用于客户自己的产品，商业获利或转许可须取得书面许可”的模式。它们未必都是当前
ASR SKU
的直接专用条款，但足以说明不能从“已经充值”推导出“可以再次销售”。[火山引擎服务条款](https://www.volcengine.com/docs/6256/64903?lang=zh)

### 2. 第 5.5 条与必须取得的书面确认

现行《产品和服务协议》第 5.5
条涉及未经许可转许可、发布、转让产品服务及权限密钥的限制。Saymore
的目标应是证明自己提供的是集成式增值服务，而不是把火山引擎能力或密钥再次交付。发布前应让火山引擎法务/商务对以下内容作
ASR 产品级书面确认：

- 付费用户属于 Saymore 客户产品的终端用户，允许开发者统一承担调用费用；
- 按小时收费和会员赠送分钟数属于 Saymore 内部计量，不构成 API/额度转售；
- 不向用户暴露长期凭证、裸 API 或可转让余额时，获准采用的客户端/代理鉴权架构；
- 获准的平台、地区、用户类型、模型版本、资源 ID 和商业期限；
- 是否需要渠道伙伴/代售资质，或普通企业客户合同已经覆盖该模式；
- 可使用的产品名称和客观披露文字，以及不得使用的商标/“官方合作”表述；
- 数据处理、留存、转委托、删除、事故通知、支持和 SLA；
- 供应商变价、停服、迁移、余额处理、用户退款和合同终止安排。

同时需要满足经营者公示、明码标价、自动续费提示、未消费权益和退款等消费者规则。应公开说明
2 元/小时是 Saymore
的服务价格，不把供应商成本价宣传成长期保证。[网络交易监督管理办法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2025/art_4b47c79b8d994a42bba4835997688faa.html)
[明码标价和禁止价格欺诈规定](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_9a1f82a007964950a1a0f6c056f2fedf.html)

### 3. 单位经济性

设 `c_h` 为每识别小时的供应商可变成本，`p_h` 为 Saymore 每小时售价，`N`
为当月有赠送权益的用户数，`g` 为每人每月赠送小时数，`H`
为用户当月另外付费使用的小时数，`F_c`
为并发计费版或商务调额产生的月度固定成本，`O`
为支付手续费、税、退款、托管、客服等其他成本：

```text
月贡献毛利 G = p_h * H - c_h * (H + N * g) - F_c - O

盈亏平衡付费小时 H_BE =
  (c_h * N * g + F_c + O - 会员订阅收入) / (p_h - c_h)
```

按调研日首页展示的 2.0 流式识别 `1.0 元/小时`作**示例**，若售价为
`2 元/小时`，未计赠送和固定费用前的单小时贡献为 `1 元`，销售额口径毛利率为
`50%`。但该价格不是长期承诺，必须以登录后的订单为准。

示例：`1,000` 名用户每月各赠 `0.5` 小时，另付费使用合计 `1,000` 小时，则收入
`2,000` 元，供应商时长成本 `1,500` 元，只剩 `500`
元覆盖并发、托管、支付、税、退款和客服；这些成本超过 `500`
元即亏损。月度赠送不是“免费”，它按活跃用户数线性消耗成本。

若采购的是固定并发版，不能在未取得报价前仍按
`1 元/小时`估算。应分别跑三种情景：只按时长收费；纯固定并发费且不收时长；固定并发费再加时长费。第三种作为未确认时的保守预算。

### 4. 并发容量公式

```text
平均活跃会话 L_avg = 月识别总小时 / (当月天数 * 24)

目标并发 C = ceil(L_avg * 峰均比 * (1 + 安全余量))
```

例如总用量 `1,500` 小时/月、30 天，平均约 `2.08` 路；若实测峰均比为 `3.5`，再留
`30%` 余量，目标为 `ceil(2.08 * 3.5 * 1.3) = 10` 路。默认 10
路此时只是勉强够用。单路在 30 天理论最多提供 720
连接小时，但真实业务受昼夜峰值、重连和会话重叠影响，不能按 100% 利用率销售。

## 七、豆包 ASR 原生准确率调优

以下能力属于 ASR
接口/自学习平台本身。大语言模型对转写结果做润色是另一层处理，可能改写原意或产生内容，不应冒充识别准确率优化。

### 1. 推荐的调优顺序

1. 先保证近讲、采样格式正确、不过载，控制环境噪声；再用真实业务音频建立固定评测集。
2. 按延迟和语言范围选择端点：普通双向 `bigmodel`、支持二遍的
   `bigmodel_async`，或更偏完整句准确率的 `bigmodel_nostream`。
3. 配置语言、ITN、标点、分句和判停，再加入行业热词、固定纠错和会话上下文。
4. 分场景做 A/B
   测试，分别统计字错率、专名命中率、首字延迟、最终句延迟和误判停；不要只凭个别样例调高热词权重。

### 2. 热词、替换词和上下文

- 平台热词表通过 `request.corpus.boosting_table_id` 或 `boosting_table_name`
  指定。中英文每个应用最多 500 张表，每表最多 5,000 个词，每词少于 10 个字，权重
  1 至 10、默认
  4，每请求只生效一张表。词表应放专名、产品名和术语，不要放常见单字。[热词使用说明](https://www.volcengine.com/docs/6561/155739?lang=zh)
- 固定纠错可使用 `correct_table_id`/`correct_table_name`；官方 2025-06
  更新支持正则替换，并支持通过 API
  管理热词表和替换词表。[产品动态](https://www.volcengine.com/docs/6561/162929?lang=zh)
- 请求级 `request.corpus.context` 可传热词或
  `correct_words`，适合当前文档、联系人或短会话中的动态词汇。平台词表、替换词和请求上下文是三层不同能力，不应互相混用。[流式识别 SDK 示例](https://www.volcengine.com/docs/6561/1395846?lang=zh)
- 2.0
  支持文本/图片上下文，但中国区具体端点和限制应实测。国际官方参数文档给出的图片限制为每请求一张、JPEG/JPG/PNG、最大
  500KB；上线仍以中国区控制台/API
  文档为准。[当前能力矩阵](https://www.volcengine.com/docs/6561/1354871?lang=zh)

### 3. 语言、文本规范化与二遍识别

- `enable_itn` 用于数字、日期等逆文本规范化；`enable_punc`
  控制标点；`enable_ddc` 控制语义顺滑。当前能力矩阵显示
  ITN/标点覆盖双向流式和流式输入，语义顺滑主要支持中英文。
- `audio.language` 仅适用于
  `bigmodel_nostream`，不要传给双向流式。双向一遍主要支持中英文；优化版二遍增加方言支持；`bigmodel_nostream`
  的语言范围更广，外语需按官方要求指定语言。
- 需要低延迟且重视最终准确率时，选择 `bigmodel_async` 并开启
  `request.enable_nonstream: true`。它先返回实时结果，VAD
  判定完整语句后再用非流式模型复识，最终结果标记为确定；旧 `bigmodel`
  不支持二遍。[大模型流式 API](https://www.volcengine.com/docs/6561/1354869?lang=zh)

公开资源 ID 能确认 1.0 小时版为 `volc.bigasr.sauc.duration`、1.0 并发版为
`volc.bigasr.sauc.concurrent`、2.0 小时版为
`volc.seedasr.sauc.duration`；没有从中国区公开资料核实到 2.0 并发版资源
ID，不应自行拼接或猜测。[资源 ID 对照](https://www.volcengine.com/docs/6348/1807452?lang=zh)

### 4. VAD、静音与分句

- 原生 WebSocket 的 `vad_segment_duration` 是语义分句最大静音阈值，默认
  3,000ms；配置 `end_window_size` 后前者失效。
- `end_window_size` 是强制判停的静音时长，默认 800ms、最小
  200ms。过短会切断犹豫或慢语速，过长会增加最终句延迟。
- `force_to_speech_time` 要和 `end_window_size` 配合；仅设置后者时，前 10
  秒可能不会判停。官方 SDK 示例建议可从约 1,000ms
  试验，但应以准确率和延迟实测决定。
- 开启二遍会自动启用 VAD。RTC 封装使用
  `VADConfig.SilenceTime`/`AIVAD`，它们不是原生 WebSocket
  参数，不要混传。[RTC ASR 参数](https://www.volcengine.com/docs/6348/1807452?lang=zh)

Saymore 首版可采用
`bigmodel_async + enable_nonstream`，为联系人/当前应用/文档提供请求级
context，后台维护产品名热词表，并让用户选择“更快结束”或“容忍停顿”两档 VAD
配置。最终参数必须用中文、英文、方言、噪声和长停顿样本分别验证；接口默认值和支持范围可能更新，以发布时中国区文档与控制台为准。

### 2. 官方事实：客户关联、结算和合同责任

《分销伙伴客户关联协议》把“最终客户/终端用户”定义为最终使用火山引擎产品或服务的公司、企业或组织，把其中实际使用的个人称为“用户”。面向大量自然人的

- 代理模式下，最终客户在官网自主下单，直接与火山引擎付款结算和开票；火山引擎直接提供服务。
- 代售模式下，伙伴与客户签约、结算和开票；火山引擎按伙伴指示提供服务。伙伴未向火山履约或发出停服指示时，客户服务可能被暂停。
- 客户通过邀约链接或纸质协议建立账号关联。主、子账号通常须为同一中国大陆实名认证主体；不同主体关系及后续账号变更要取得火山书面同意。
- 同一客户账号不能同时拥有代理和代售身份。代售关联通常要求账号无生效订单、未使用资源、欠款、余额、代金券等，官方建议使用新账号。
- 代售客户不能独立充值或申请信控，只能使用伙伴分配的虚拟额度下单消费。虚拟额度是客户账号的结算工具，不是可下发给
  Saymore 用户的 API 调用凭证。
- 为合作、结算和客户管理，客户授权火山向伙伴同步账号
  ID、实名认证名称、联系方式、订单和账单等信息。解除关联通常需要伙伴和火山确认；解除后关联权益终止，部分订单不支持变更或退款。

伙伴可支配虚拟额度等于伙伴可用余额减去已分配给关联客户的剩余额度；伙伴可以转入和转出额度。公开页面没有给出豆包
ASR
的伙伴折扣率、返佣、最低采购额、消费者转售权或统一凭证下发权，这些不能从“全线产品可分销”推断。[代售交易模式](https://www.volcengine.com/docs/40915/1112485?lang=zh)
[伙伴虚拟额度管理](https://www.volcengine.com/docs/40915/1112492)
[代售客户关联问答](https://www.volcengine.com/docs/40915/1112488)

### 3. 官方事实：ASR 鉴权与短期令牌

当前大模型流式 ASR WebSocket 推荐在握手头使用控制台生成的 `X-Api-Key`，并携带
`X-Api-Resource-Id` 和每次连接唯一的 `X-Api-Connect-Id`；旧版兼容方式为
`X-Api-App-Key` + `X-Api-Access-Key`。官方移动 SDK 示例同样要求开发者配置
AppID、Access Token 和 Resource
ID；官方快速入门要求妥善保管这些服务调用校验信息。[大模型流式识别 SDK](https://www.volcengine.com/docs/6561/1395846?lang=zh)
[豆包语音快速入门](https://www.volcengine.com/docs/6561/163043?lang=zh)
[BytePlus 官方流式 ASR 协议](https://docs.byteplus.com/id/docs/byteplusvoice/asrstreaming)

截至调研日，官方公开资料中**没有找到** `openspeech` 数据面支持以下能力：用长期
ASR Key 换取短期 WebSocket 令牌；绑定某个 Saymore
用户、设备或会话；为令牌设置独立时长/并发上限；即时撤销单个终端令牌。控制台配额查询
OpenAPI 虽可使用 IAM/STS 临时 AK/SK 和 `X-Security-Token`，但它调用的是
`open.volcengineapi.com` 管理面，不能据此认为 STS 可用于
`openspeech.bytedance.com/api/v3/sauc/*`
数据面。[QPS/并发查询接口](https://www.volcengine.com/docs/6561/1476626?lang=zh)

官方 SDK 能在客户端配置
Token，只证明技术接口支持设备直连，不证明伙伴可以把统一生产凭证公开分发，也不证明泄露和盗刷责任转移给平台。分销身份没有改变
ASR 鉴权协议。除非火山引擎书面提供 ASR 专用短期凭证并授权使用，统一
`X-Api-Key`/Access Token 应只保存在可信代理中。

### 4. 工程建议：三种伙伴模式映射到两种代码架构

```text
代理或代售企业客户 / BYOK
Saymore desktop -> openspeech WebSocket
                   企业客户自己的账号、Key、订单和配额

经销、集成或 Saymore 统一付费
Saymore desktop -> Saymore ASR gateway -> openspeech WebSocket
                   用户授权/计量/全局并发       统一供应商 Key
```

代理客户由火山直接签约；代售客户虽由伙伴结算，也仍有自己的关联火山账号。因此这两种标准企业分销路径优先让客户使用自己的凭证直连。经销/集成/产品合作若合同允许
Saymore 把 ASR 作为软件内服务统一提供，也不应把供应商 Key
下发客户端，而应经代理；伙伴身份和数据面密钥安全是两个独立问题。

BYOK 可继续使用现有 `crates/infra::VolcengineSpeechRecognizer`。统一付费模式新增
`ProxySpeechRecognizer`，同样实现 `crates/app` 的 `StreamingSpeechRecognizer`
端口；`crates/app` 只保留会话、错误和用例语义，不依赖
HTTP/WebSocket、火山协议或计费数据库，`apps/desktop`
根据授权类型装配直连或代理实现。

远端网关是独立部署和安全边界，宜放独立服务仓库；若必须共同版本管理，则使用专门的
`services/asr-gateway` 工作区成员。不要放入 `apps/desktop`，也不要让
`crates/app` 依赖服务端框架。

### 5. 工程建议：最小代理协议

```text
POST /v1/asr/sessions
Authorization: Bearer <Saymore user token>
Idempotency-Key: <uuid>

request:  { device_id, model, audio_format, expected_max_ms }
response: { session_id, websocket_url, one_time_ticket,
            ticket_expires_at, remaining_ms }

GET /v1/asr/sessions/{session_id}/stream
Authorization: Ticket <one_time_ticket>
Upgrade: websocket
```

- Saymore 用户令牌由许可证/账户服务签发；WebSocket ticket 再缩短到约 30 至 60
  秒、单次使用，并绑定用户、设备、session ID、模型和最大时长。它是 Saymore
  自己的票据，不冒充火山令牌。
- 网关验证套餐余额和单用户并发，原子获取全局并发租约后才连接火山。火山 Key
  从密钥管理服务加载，只写入上游握手头，不进入响应、日志或桌面进程。
- 第一版可让桌面继续发送火山二进制帧，网关校验帧类型、解压上限和音频格式后转发；服务端按实际接受的
  PCM
  字节数和采样率计算时长，不能相信客户端上报的分钟数。响应帧可原样返回，以减少现有
  Rust 识别器改造。
- 限制每帧大小、发送速率、会话最长时长、空闲超时、用户/设备并发及每日预算；拒绝未知模型、资源
  ID 和客户端自定义上游地址，防止代理变成通用隧道。

### 6. 工程建议：计量与全局并发租约

会话账本至少记录 `session_id`、用户、套餐、上游 connect ID/log
ID、状态、已接受音频毫秒、最终结果状态、零售扣减、错误类别和时间戳；不记录音频和转写正文。创建和终结使用幂等键，状态只按
`reserved -> connected -> streaming -> finalized/failed/cancelled` 单向推进。

多实例网关不能用进程内 semaphore
控制总并发。应在强一致共享存储中原子完成“清除过期租约、比较当前数量和供应商上限、写入带
fencing token 的租约”。租约使用短 TTL 并续约，WebSocket
关闭后显式释放，实例崩溃后由 TTL
回收；只有拿到租约的请求才能建立上游连接，并预留运维/重连容量。供应商触发限流时短暂熔断，以控制台
`value/limit` 和账单校准本地上限。

零售额度采用“预留最大额度、流中累计、成功后结算、差额释放”，避免并发请求透支。供应商计费取整、中途断线和重试规则没有在公开流式
ASR 资料中明确，不能把内部秒级计量声称为供应商账单；应每日对账并留成本缓冲。

### 7. 工程建议：错误、断线与退款

BytePlus
官方对应协议列出参数错误、空音频、等待数据包超时、音频格式错误、内部错误和服务繁忙，错误帧类型为
`0b1111`。当前公开表没有“并发超限”的唯一数值码，`55000031`
只能解释为服务繁忙，不能固定解释为并发不足。中国区 SLA
只确认超过配额会被限流/频控，并将其排除在平台失败请求之外。[智能语音 SLA](https://www.volcengine.com/docs/6561/107349?lang=zh)

| 情况                           | 客户端行为                           | 零售计量建议                                         |
| ------------------------------ | ------------------------------------ | ---------------------------------------------------- |
| 登录失效、无套餐、参数非法     | 建连前拒绝，不重试                   | 不扣额度                                             |
| 全局并发已满                   | 返回 `busy` 和短退避时间，不无限排队 | 不扣额度                                             |
| 上游鉴权、欠费或资源未开通     | 熔断该模型并告警                     | 不扣用户额度                                         |
| 服务繁忙且尚未发送音频         | 有界指数退避，只重试建连             | 不扣额度                                             |
| 传输中断且没有最终文本         | 结束该 attempt，不自动重放已确认音频 | 默认释放用户预留额度，供应商成本作为故障损耗并待对账 |
| 用户主动取消或已有可用最终文本 | 立即关闭上下游并释放租约             | 按公开套餐规则结算已接受时长                         |

公开资料没有承诺流式 ASR
自动重连、断点续传、请求去重计费或失败免费。识别状态依赖完整前文，重放尾部可能产生错误文本，重放全部音频又可能重复产生供应商成本。因此首版把断线视为
attempt
失败；保留本地录音用于重试必须另行取得用户同意。退款/额度返还写入不可变账本并使用幂等键，支付退款与云识别分钟返还分开处理。

### 8. 分阶段实现

1. **合同验证：**向火山引擎提交 Saymore B2B/B2C
   两套流程图，确认代理、代售、经销、集成或产品伙伴模式，写明 ASR
   SKU、消费者使用权、统一计费和密钥架构；未书面确认前不销售“豆包额度”。
2. **保留
   BYOK：**先维持企业/个人自带凭证直连，验证识别质量和真实并发；它不使用开发者统一账单。
3. **封闭代理试点：**实现单区域网关、Saymore
   ticket、供应商密钥隔离、服务端音频计量和容量硬上限；少量邀请用户，不承诺自动续传。
4. **付费放行：**引入强一致全局租约、幂等额度账本、套餐预留/结算、退款工作流、账单对账、密钥轮换和告警后再开放统一付费。
5. **规模化：**建设多可用区、故障演练、供应商配额降级和企业客户独立账号路由；只有火山正式提供
   ASR 短期终端令牌时，才评估只保留控制面、让音频直连。

## 九、多账号池、Supabase 与网关容量

### 1. 官方事实：多账号是治理工具，不是已授权的并发叠加方式

没有在火山引擎公开的 ASR
专用文档或通用协议中找到一句直接写明“禁止同一主体注册多个账号并轮询 ASR
请求”。因此不能把“多账号必然违规”写成已证实事实。火山引擎也确实提供企业组织功能，允许企业以公司、部门或项目关系管理多个均已实名认证的成员账号，用于资源、身份、权限和费用隔离。[企业组织管理服务协议](https://www.volcengine.com/docs/6256/105181?lang=zh)
[多账号资源治理方案](https://www.volcengine.com/docs/84627/1321812?lang=zh)

但官方《产品和服务协议》第 1.4
条明确规定，产品会按订购类别、特性和规格限制使用方式、范围和功能；客户应遵守该等限制，超过购买规格时火山引擎可以限制或暂停服务。付款主体还应与注册或实名认证主体一致。[产品和服务协议](https://www.volcengine.com/docs/6256/68938?lang=zh)

ASR 配额查询接口进一步显示，查询必须同时提供 `AppID` 和资源
ID，并校验“应用和账号”的从属关系；返回的 `limit` 是服务开通或购买时确定的
QPS/并发上限。这说明每个可用配额都依附于正式开通/购买的账号与应用关系，而不是网关自行合并后形成一个获得官方承诺的总配额。[QPS/并发查询接口](https://www.volcengine.com/docs/6561/1476626?lang=zh)

**工程与合同判断：**同一真实企业合法管理多个成员账号并非天然禁止，但若注册或借用
10 至 20
个账号的目的就是汇总每个账号的默认并发、绕过增购并发并向终端用户转售，公开资料没有提供这种授权，而且与“遵守已购买服务规格”的要求存在明显冲突风险。火山引擎安全规则适用于渠道商，并保留对违规、影响平台或其他用户稳定的行为停服和关停账号的权利。[信息与网络安全规则](https://www.volcengine.com/docs/6256/79758?lang=zh)

因此不应把账号池作为默认架构。只有分销/OEM/产品合作补充协议明确写明下列内容后，才实施多上游账号路由：允许同一签约主体聚合的账号数量、每个账号归属、统一服务自然人用户的权利、总并发、故障切换和结算方式。不得使用员工、亲友或其他公司的实名账号拼池。

### 2. 官方事实：Supabase Free 能覆盖哪些后台能力

Supabase 每个项目提供 Postgres、自动 API、Auth、Edge Functions、Realtime 和
Storage，因而可以集中承载 Saymore
的账户登录、用户资料、套餐、分钟账本和短时控制接口。[Supabase 平台说明](https://supabase.com/docs/guides/platform)

截至调研日，Free Plan 的主要公开额度为：最多两个活跃免费项目；`50,000`
月活认证用户；每项目 `500 MB` 数据库；`1 GB` 文件存储；`5 GB` 非缓存出口流量和
`5 GB` 缓存出口流量；每月 `500,000` 次 Edge Function 调用；Realtime 峰值 `200`
连接、每月 `200 万` 条消息、单消息最大
`256 KB`。免费版只有一天日志，不提供自动备份、PITR、可用性 SLA
或自定义域名。[Supabase 价格与额度](https://supabase.com/pricing)

这些数字不能直接解释成适合生产：数据库超过 `500 MB`
会进入只读状态；低活跃免费项目在七天窗口内可能被暂停，暂停后只有 90
天恢复窗口；内置 Auth
邮件提供方的注册、找回等邮件合计只有每项目每小时两封，正式运营必须配置自己的
SMTP。[数据库大小限制](https://supabase.com/docs/guides/platform/database-size)
[免费项目暂停规则](https://supabase.com/docs/guides/platform/free-project-pausing)
[Auth 速率限制](https://supabase.com/docs/guides/auth/rate-limits)

因此 Supabase Free
适合作为开发和小流量封闭试点的一站式**账户、数据库和短控制面**，但不能据此承诺生产可用性，也不应承担持续音频数据面。

### 3. 官方事实：Edge Functions 能代理 WebSocket，但有硬时限

Supabase Edge Functions 技术上支持入站及出站
WebSocket，官方文档也明确给出将二者组合成 WebSocket 代理的用法。但 WebSocket
仍受 worker 的 wall-clock、CPU 和内存限制；`waitUntil()`
只能避免连接被误判为空闲而提前回收，不能延长硬上限。[WebSocket 支持](https://supabase.com/docs/guides/functions/websockets)
[WebSocket 提前断开说明](https://supabase.com/docs/guides/troubleshooting/edge-functions-worker-timeouts-and-websocket-drops)

托管 Edge Functions 的当前限制包括：最大内存 `256 MB`；Free worker 最长 `150`
秒，付费版最长 `400` 秒；每请求最大 CPU 时间 `2` 秒；请求空闲超时 `150`
秒。[Edge Functions 限制](https://supabase.com/docs/guides/functions/limits)

**工程判断：**这意味着免费函数中的一次长听写最迟约 2.5
分钟就会被硬终止，付费函数也约为 6 分 40
秒。客户端周期性重连虽能绕过单次时长，却会切断识别上下文、增加失败和重复计费边界，不能当作可靠的桌面连续听写方案。Edge
Functions 可以负责登录后创建会话、检查余额和签发一次性
ticket；音频双向代理应部署到支持可配置长连接时限的托管容器。Supabase Realtime 的
`200` 连接额度是 Realtime 产品配额，不是 Edge Function ASR 代理的并发额度。

### 4. 工程推算：音频网关的性能和带宽

网关不做声学推理，只执行鉴权、帧校验、有限缓冲和双向转发，CPU
通常不是首要瓶颈。采用有界缓冲并禁止积压整段音频后，单连接内存也较低；真正约束是供应商并发、长连接稳定性、出口带宽和平台时限。

对 Saymore 当前常见的 `16 kHz × 16 bit × 单声道 PCM`，未压缩音频吞吐为：

```text
16,000 sample/s × 2 byte/sample = 32,000 byte/s
32,000 × 3,600 = 115.2 MB/小时/方向
代理接收客户端并发送上游：总搬运约 230.4 MB/小时
```

这是工程推算，不是供应商账单。10 路同时听写约为每方向
`2.56 Mbps`、双向搬运合计约 `5.12
Mbps`；20 路翻倍为每方向 `5.12 Mbps`、合计约
`10.24 Mbps`。识别文本返回量相对很小，WebSocket/TLS
协议有额外开销，若上游支持压缩音频则数字会变化。

Supabase 把从其服务器发出的数据库、Storage 和 Function
数据纳入出口流量统计。若音频由 Function 转发至豆包，至少上游方向的原始 PCM 约为
`115.2 MB/小时`；按 Free 的 `5 GB` 非缓存出口额度粗算，约 `43`
小时便会耗尽，尚未计协议、文本、数据库响应或其他业务流量。出站到第三方 API
的精确计费归类仍应向 Supabase
确认，不能只按该估算做预算。[出口流量说明](https://supabase.com/docs/guides/platform/manage-your-usage/egress)

### 5. 工程建议：只有 PostgreSQL 也能实现 10 至 20 路全局并发

Redis 不是这个规模的前置条件。Supabase 提供完整
PostgreSQL，并允许把数据库函数作为 RPC 调用；PostgreSQL
本身支持事务、行锁和事务级 advisory
lock。[Supabase 数据库说明](https://supabase.com/docs/guides/database/overview)
[PostgreSQL Advisory Lock](https://www.postgresql.org/docs/current/functions-admin.html#FUNCTIONS-ADVISORY-LOCKS)

建议建立两类表：

### 6. 官方事实与合规判断：Supabase 没有中国大陆托管区域

Supabase
当前列出的亚洲区域包括新加坡、东京、首尔和孟买，没有中国大陆区域；官方也建议选择最靠近用户的区域以降低延迟。[可用区域](https://supabase.com/docs/guides/platform/regions)

**合规与架构判断：**如果中国大陆用户的原始语音先进入 Supabase 新加坡等境外
Function，再转回中国大陆的豆包

Supabase 境外边缘。可以仅让 Supabase
